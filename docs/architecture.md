# Устройство проекта

## Границы модулей

```text
index.html                 HTML оболочка и начальная клавиатура пианино
assets/styles.css          стили и две темы
src/app.mjs                выбор режима по URL
src/core/                  общие механизмы
src/instruments/piano/     пианино и его звук
src/instruments/tenorion/  сетка Tenori-on и его звук
src/instruments/drums/     ударные, соответствие нот и семплы
src/instruments/synth/     контроллер, пульт, модель нот и аудио
src/instruments/recorder/  вспомогательное окно записи
scripts/                   проверки и версии ресурсов
tests/                    тесты (без браузерных зависимостей)
```

Чистые модели и аудиофункции не обращаются к DOM. Контроллер инструмента связывает его интерфейс с состоянием и звуком. Пульт синтезатора сообщает об изменениях через callback; не управляет сохранениями или запуском проигрывателя.

## Общая основа

| Модуль | Ответственность |
| --- | --- |
| `transport.mjs` | BPM, общая фаза, BroadcastChannel и Web Locks |
| `scheduler.mjs` | одно планирование звука на 200 мс вперёд, визуальные таймеры, остановка и возврат из фона |
| `playback-control.mjs` | асинхронный запуск, защита от повторного запуска и отмена незавершённого AudioContext.resume |
| `sections.mjs` | четыре секции, положение шага, миграция boolean сеток и переключатель секций |
| `storage.mjs` | проверяемое чтение session/local сохранений, запись при ограничениях iframe |
| `widget-storage.mjs` | идентичность экземпляра виджета без изменения URL |
| `keyboard-map.mjs`, `live-keyboard.mjs` | физические клавиши, отпускание, фокус и экранная клавиатура |
| `microphone.mjs`, `sample-store.mjs` | запись, освобождение микрофона, тишина и IndexedDB |

### Время и аудио

`transport` определяет глобальный шаг по Unix time. `scheduler` переводит его в время AudioContext. `onStep({step, time, first})` планирует звук, `onVisual(step)` обновляет экран на границе шага. `first` нужен для вступления в середину длинной ноты после запуска, смены темпа или фоновой паузы.

`reset()` удаляет старые визуальные задачи и начинает новое планирование. Уже поставленные в Web Audio звуки отменяет контроллер инструмента; живые голоса клавиатуры должны оставаться независимыми от секвенсора. `stop()` очищает interval и timeout; запоздавшие визуальные callbacks проверяют поколение запуска и не меняют остановленный интерфейс.

Кнопки запуска подключаются через `bindPlayback`. Остановка должна вызывать `cancelStart()`: это предотвращает поздний запуск после разрешения аудио, когда пользователь уже остановил инструмент или начал запись.

### Совместимость сохранений

Не меняйте существующие ключи хранения и число секций без явной миграции. Сначала проверяйте сохранение, затем принимайте его. Новое поле должно иметь значение по умолчанию и проверяемый диапазон. `restoreSynth(..., {strict:true})` позволяет отличить повреждённую запись от пустого рисунка.

Для данных виджета используйте `widgetStorageKey`; для общих BPM — ключ транспорта. Не храните AudioNode, AudioBuffer или DOM в JSON. Blob записей хранится отдельно в IndexedDB. Удаление интерфейса записи не означает удаления существующих Blob.

## Добавление инструмента

1. Создайте каталог `src/instruments/<mode>/` с контроллером и отдельной чистой моделью состояния.
2. Добавьте режим в реестр `src/app.mjs`. Существующие URL должны продолжать работать.
3. Используйте общую клавиатуру, сохранения и, если нужен ритм, transport/scheduler/playback-control.
4. Обрабатывайте остановку при `pagehide`, незавершённый запуск и возвращение из фона. Освобождайте микрофон и AudioNode после окончания звука.
5. Добавьте тесты модели, миграций и специфичных аудиопараметров. Проверяйте границы секций и изоляцию экземпляров.
6. Проверьте обе темы в 376×376, клавиатуру, фокус, запуск/остановку, сохранение после reload и ошибки браузера.
7. Выполните `npm run version-assets`, затем `npm run check` и отправьте рабочую ветку.

## Проверки и ресурсы

`npm run check` не требует npm install. Тесты используют встроенный Node test runner; часы и таймеры планировщика подменяются, поэтому проверки не зависят от ожидания реального времени.

Версия ресурсов — хеш содержимого HTML, кода и стилей. Скрипт обновляет ссылки в HTML, статические импорты и реестр динамических импортов одним значением. Не редактируйте `?v=` вручную. CI отклоняет забытые версии и отсутствующие файлы импортов. После структурных изменений дополнительно нужен браузерный прогон: проверки Node не подтверждают корректность DOM и реального микрофона.
