# Устройство проекта

## Границы модулей

```text
index.html                 HTML оболочка с корневым элементом React
assets/styles.css          сгенерированный CSS для браузера
src/styles.css             порядок подключения CSS
src/styles/                базовые стили и общая оболочка
src/app.tsx                выбор режима по URL
src/core/                  общие механизмы
src/ui/                    общие React-компоненты и их CSS
src/instruments/piano/     пианино и его звук
src/instruments/tenorion/  сетка Tenori-on и его звук
src/instruments/drums/     ударные, соответствие нот и семплы
src/instruments/synth/     контроллер, пульт, модель нот и аудио
src/instruments/recorder/  вспомогательное окно записи
scripts/                   проверки и версии ресурсов
tests/                    тесты моделей, аудио и React (jsdom)
```

Чистые модели и аудиофункции не обращаются к DOM. Контроллер инструмента связывает его интерфейс с состоянием и звуком. Пульт синтезатора сообщает об изменениях через callback; не управляет сохранениями или запуском проигрывателя.

## Общая основа

| Модуль | Ответственность |
| --- | --- |
| `transport.ts` | BPM, общая фаза, BroadcastChannel и Web Locks |
| `scheduler.ts` | одно планирование звука на 200 мс вперёд, визуальные таймеры, остановка и возврат из фона |
| `sequencer-engine.ts` | общий асинхронный запуск, остановка, темп и отмена незавершённого AudioContext.resume |
| `sections.ts` | четыре секции, положение шага, миграция boolean сеток; переключатель находится в `ui/controls.tsx` |
| `storage.ts` | проверяемое чтение session/local сохранений, запись при ограничениях iframe |
| `widget-storage.ts` | идентичность экземпляра виджета без изменения URL |
| `keyboard-map.ts`, `live-keyboard.ts` | физические клавиши и отпускание; интерфейс — в `ui/keyboard.tsx` |
| `microphone.ts`, `sample-store.ts` | запись, освобождение микрофона, тишина и IndexedDB |

### Время и аудио

`transport` определяет глобальный шаг по Unix time. `scheduler` переводит его в время AudioContext. `onStep({step, time, first})` планирует звук, `onVisual(step)` обновляет экран на границе шага. `first` нужен для вступления в середину длинной ноты после запуска, смены темпа или фоновой паузы.

`reset()` удаляет старые визуальные задачи и начинает новое планирование. Уже поставленные в Web Audio звуки отменяет контроллер инструмента; живые голоса клавиатуры должны оставаться независимыми от секвенсора. `stop()` очищает interval и timeout; запоздавшие визуальные callbacks проверяют поколение запуска и не меняют остановленный интерфейс.

Кнопки запуска вызывают `sequencer-engine.toggle()`. `stop()` и `dispose()` отменяют незавершённый запуск: поздний AudioContext.resume не начинает воспроизведение после остановки, записи или размонтирования.

### Совместимость сохранений

Не меняйте существующие ключи хранения и число секций без явной миграции. Сначала проверяйте сохранение, затем принимайте его. Новое поле должно иметь значение по умолчанию и проверяемый диапазон. `restoreSynth(..., {strict:true})` позволяет отличить повреждённую запись от пустого рисунка.

Для данных виджета используйте `widgetStorageKey`; для общих BPM — ключ транспорта. Не храните AudioNode, AudioBuffer или DOM в JSON. Blob записей хранится отдельно в IndexedDB. Удаление интерфейса записи не означает удаления существующих Blob.

## Добавление инструмента

1. Создайте каталог `src/instruments/<mode>/` с контроллером и отдельной чистой моделью состояния.
2. Добавьте режим в реестр `src/app.tsx`. Существующие URL должны продолжать работать.
3. Используйте общую клавиатуру, сохранения и, если нужен ритм, transport/scheduler/sequencer-engine.
4. Обрабатывайте остановку при `pagehide`, незавершённый запуск и возвращение из фона. Освобождайте микрофон и AudioNode после окончания звука.
5. Добавьте тесты модели, миграций и специфичных аудиопараметров. Проверяйте границы секций и изоляцию экземпляров.
6. Проверьте обе темы в 376×376, клавиатуру, фокус, запуск/остановку, сохранение после reload и ошибки браузера.
7. Выполните `npm run build`, затем `npm run check` и отправьте рабочую ветку.

## Проверки и ресурсы

Перед проверками выполните `npm ci`. Тесты используют встроенный Node test runner; часы и таймеры планировщика подменяются, поэтому проверки не зависят от ожидания реального времени.

Версия ресурсов — хеш содержимого HTML, кода и стилей. Скрипт обновляет ссылки в HTML, статические импорты и реестр динамических импортов одним значением. Не редактируйте `?v=` вручную. CI отклоняет забытые версии и отсутствующие файлы импортов. После структурных изменений дополнительно нужен браузерный прогон: проверки Node не подтверждают корректность DOM и реального микрофона.

## TypeScript и сборка

Все рабочие модули находятся в `src/**/*.ts` и `src/**/*.tsx`. Строгие настройки задаются `tsconfig.json`; библиотечные контракты браузера дополняет `src/browser.d.ts`. `dom.ts` проверяет наличие и тип элементов, `guards.ts` проверяет внешние значения и индексы массивов. Состояния, ноты, параметры, голоса и сообщения имеют явные типы.

Импорты используют `.js`, чтобы компилятор и браузер разрешали одинаковые пути. `npm run build` сначала проверяет типы, затем компилирует модули, собирает React в автономный `site/app.js` через esbuild и генерирует версии ресурсов. Также esbuild собирает `src/styles.css` и его импорты в `assets/styles.css`. Не редактируйте `site/` и `assets/styles.css` вручную. Тесты запускаются на скомпилированных модулях; сборка не требует зависимости в браузере.

## Интерфейс React

- `ui/focus.tsx`: индикатор и активация фокуса, подписки снимаются при размонтировании.
- `ui/keyboard.tsx`: общая клавиатура и `useKeyboard`. Подписка на физические клавиши создаётся один раз; обновление параметров и подписей не переинициализирует удерживаемые ноты.
- `ui/controls.tsx`: заголовок, воспроизведение, редактирование чисел и четыре секции.
- `ui/grid.tsx`: сетка, фокус стрелками и протягивание нот синтезатора. Стабильные ключи сохраняют DOM и фокус при обновлении шага; переключение секции отменяет незаконченный жест.
- `ui/hooks.ts` и `core/observable.ts`: жизненный цикл контроллера и уведомления React.
- `instruments/*/*-view.tsx`: составление экранов из общих компонентов. Контроллеры `.ts` содержат музыкальную логику, `synth-panel.tsx` — переключение огибающих и настройки фильтра.
- `ui/adsr.tsx`: общий редактор ADSR с захватом указателя, клавиатурным управлением и отдельными доступными точками. Принимает `ADSR` и callback; не зависит от синтезатора или аудио.
- `core/envelope.ts`: тип ADSR, диапазоны, форматирование и геометрия. Временные стадии используют отдельные логарифмические области редактирования, чтобы короткую атаку можно было менять на небольшом экране. График не имеет линейного масштаба секунд.

У каждого голоса синтезатора независимая огибающая фильтра. Она поднимает частоту от cutoff на глубину до пяти октав с ограничением ниже Nyquist, затем возвращает её при отпускании ноты. Обновления параметров удерживаемой ноты сохраняют источник и отсчитывают стадии от её исходного начала. Старые сохранения получают `filterAmount: 0`, поэтому их тембр сохраняется.

Не создавайте AudioContext, планировщики или подписки при рендеринге компонента. Контроллер создаётся лениво и подключается в эффекте; очистка останавливает звук, таймеры, каналы, обработчики клавиатуры и микрофон. Таймеры Web Audio не запускаются эффектами, зависящими от параметров интерфейса.

У нового инструмента нужны контроллер с `connect(): () => void` и подпиской на обновления, экран React и запись в реестре `app.tsx`. При добавлении UI сначала используйте общий компонент; аудиотесты запускаются независимо от React, компонентные проверки — в jsdom.

## Стили компонентов

CSS лежит рядом с компонентом с тем же именем: `ui/adsr.tsx` / `ui/adsr.css`, `ui/keyboard.tsx` / `ui/keyboard.css`, `instruments/synth/synth-panel.tsx` / `synth-panel.css`. Общие компоненты имеют один файл стилей независимо от числа использующих их инструментов. Стили экрана принадлежат `*-view.css`; обе темы, состояния и адаптивные правила хранятся вместе со стилями владельца.

`styles/base.css` содержит настройки документа, базовую типографику и `[hidden]`; `styles/layout.css` — общую оболочку виджетов. `src/styles.css` содержит только CSS-импорты в явном порядке. При добавлении компонента создайте соседний CSS и добавьте его импорт сюда. В React и аудиомодули CSS не импортируется: скомпилированные компоненты также используются в тестах Node без браузерного загрузчика стилей.

Используйте классы владельца (`adsr-*`, `focus-*`, `synth-panel`, и т. д.), чтобы правило не затрагивало чужие компоненты. Разделение файлов не создаёт автоматической изоляции селекторов. esbuild проверяет импорты и собирает один CSS для быстрой загрузки; CI проверяет форматирование исходного CSS и актуальность сгенерированного файла.

## Редактирование записей

`core/sample-edit.ts` содержит проверку `SampleSettings {gain, start}` и расчёт пиков волны всех каналов. `ui/sample-editor.tsx` / `.css` — общий редактор: громкость, начало, волна с захватом указателя и прослушивание через callback. Волна нормализована для видимости тихих записей; аудиобуфер при редактировании не изменяется.

Контроллер драм-машины хранит четыре набора настроек под `widgetStorageKey("drum-sample-settings-v1")`; исходные Blob по прежним ключам IndexedDB. Старые записи получают gain=1/start=0. Восстановленное начало ограничивается фактической длительностью после декодирования. Новая запись сбрасывает только настройки своей дорожки и открывает редактор. `drumSampleVoice` применяет gain и start к одному общему пути прослушивания, клавиатуры и секвенсора; края получают короткий fade по оставшейся длительности.
